## 职责边界

- 本文件确认源材料的页数、顺序、标题、页内内容归属、原始信息模块、关键事实/术语/数据和待核实问题。原始文件保持不变。
- 每页沿用原始大纲的 Markdown 层级：`## 第 N 页｜页面标题` → `### 页面内容` → `#### 内容小标题`。`页面内容`是容器；其直接小标题是“每块内容怎么处理”的候选项。
- `### 页面标注`、`### 页面布局建议`、`### 生成图片要求`、`### 图片提示词草案`仅在原材料已有时保留为与`页面内容`并列的栏目；它们不属于内容处理项。不得借整理大纲之机新增视觉方向、配色、版式、素材用途、标题样式或提示词策略，这些选择由决策板和后续阶段负责。
- 表格行名、列表项、加粗短语和正文段落属于其所在内容块，不自动升格为小标题。原文没有小标题的单块正文或表格直接放在`页面内容`下；不要编造一个看似来自原文的标题。
- 原始表格含合并单元格时，可在 Markdown 中使用 HTML 表格块，以 `rowspan` / `colspan` 明确保留合并关系，决策板预览支持这两项属性。普通管道表格则把合并值重复填入其覆盖的每一行，并在“页面布局建议”注明视觉合并要求。不要用无说明的空白单元格暗示沿用上一格，也不要自行扩展不确定的合并关系。生成与 QA 必须按实际跨行、跨列范围核对数据归属。
- 对源材料中确有先后、因果、输入输出或阶段推进关系的内容，保留节点原文、顺序与关系，并用最清楚的结构表达；可用箭头、编号、分层或文字说明，不固定为箭头。并列分类不得串成流程。整理时新增的箭头、编号等连接记号只用于表示结构，不视为必须呈现在图片中的原文信息；源材料本身有明确的方向或循环要求时仍须保留其含义。

## 审阅清单

- 页数、顺序和标题是否与原材料一致。
- 每页的实质内容是否都位于`页面内容`下，内容小标题是否与原文一一对应，原文无小标题的正文或表格是否仍完整保留。
- 页面标注、布局建议、生成要求和提示词草案如来自原材料，是否保留在独立栏目，且没有被当成内容处理项。
- 是否遗漏定义正文、功能清单、参数维度、应用场景、案例阶段、表格或无小标题的内容。
- 流程节点、顺序、分支与因果关系是否准确；并列信息是否避免被误写成流程；整理时新增的连接记号是否没有混入节点原文。
- 关键事实、术语和数据是否准确；疑点与待确认问题是否已明确记录。
