## Slide 01：

- 页面标题：沿用确认大纲标题，不得主动改写或压缩。
- 页面类型：正文承载页 / 功能概览页 / 混合页 / 证据页 / 架构页等；当页面可能在正文保留和模块化概览之间摇摆时，先询问用户倾向，不要默认压缩正文。
- Decision Board 映射：说明 `page_mode`、`density` 和 `page_treatment` 如何影响本页页面类型、正文保留比例、模块数量、视觉强度和空间预算；说明 `information_groups`、`group_weights` 和 `primary_emphasis_method` 如何影响阅读顺序、信息完整度、视觉锚点大小和面积分配。如果本页因内容角色需要偏离确认倾向，必须写明原因。
- 类型取舍说明：正文承载页保留更多原文和完整定义，但必须通过主视觉、分区、重点标注和留白避免纯文本平铺；功能概览页更模块化、更适合快速扫读，但会压缩原文；混合页保留一段核心正文，再搭配少量能力模块。
- 页面角色与目标：
- 原始输入摘要与信息优先级：
- 视觉模式：
- 画面主次与侧重点：说明本页是主视觉、支撑视觉还是阅读优先；如果同时选择了视觉侧重点标签、信息组权重、重点表达方式或自定义意图，说明它们如何约束主视觉大小、文本保留比例、阅读顺序和辅助内容降级。明确写出“主重点是否通过面积、阅读、视觉锚点或路径来突出”。
- 主视觉与辅助模块：
- 主重点表达方式：若 `primary_emphasis_method=reading-priority`，主重点应拥有最高阅读优先级、最多文本保留和最清楚的标签/层级，但不必占最大面积；若为 `area-priority`，主重点可占最大主体区域；若为 `visual-anchor`，主重点应通过强视觉对象或场景成为记忆点；若为 `path-priority`，主重点应通过流程、连接或因果路径组织。
- 配色角色：本页背景、主强调、辅助对比、功能色与材质色如何使用；说明和项目色彩策略的关系。
- 色彩占比与变化：本页的主色、辅色、强调色大致比例；与前后页相比哪里保持一致、哪里按页面角色变化。
- 青橙使用判断：本页是否使用青色 + 橙色；若使用，说明它们各自承担的语义角色、占比和强度限制；若不使用，说明替代色彩方向。不得把青橙作为默认科技/商业配色。
- 组件级色彩分工：重复模块的背景、边框、icon、小标题、正文、关键数字、装饰线、状态色分别如何处理；明确哪些层级不能同色或同亮度。
- 视觉强度表：S 级主视觉、A 级关键结论/数字、B 级模块标题、C 级正文、D 级背景装饰分别使用什么尺寸、亮度、颜色和材质强度。
- 反模板风险：本页最容易落入的 AI 味配色或同质化问题，以及生成时需要明确禁止的颜色组合。
- Title Zone：标题禁区占比、局部背景要求、首个主体模块起点。
- Content Blueprint：主体可用区域、主视觉锚点、模块栅格、底部安全线。
- Composition Pattern：说明页面采用哪种构图关系，例如“产品锚点 + 功能清单 + 底部场景支撑”、“上方定义面板 + 中部系统矩阵 + 右侧证据带”、“中心流程路径 + 两侧证据模块”。避免只按信息权重把页面粗暴切成等大块或满屏卡片。
- Alignment Contract：为每页定义一个主内容父框，例如 `content frame x=56-1544, y=165-835`。所有一级视觉区（上方说明区、证据区、应用场景区、设备示意带、下方矩阵、结论条等）必须说明是否共享该父框的左边界、右边界、列宽、行高、中心线或基线。多区页面不得只写“左侧/右侧/下方”；必须写清父容器和子模块关系，尤其说明上方模块组合是否与下方主矩阵两端对齐。
- Space Budget：为高密度页面分配纵向空间预算，写明标题安全区、定义/说明区、辅助图片区、主内容区和底部安全线的大致高度。标题安全优先使用局部避让，不默认把整页内容整体下移。
- Main Content Comfort：为页面主内容定义最低舒展度，例如主矩阵、核心功能区、对比表、流程图或架构层至少占页面可用高度的比例，或每个核心模块的最低高度。若空间不足，先压缩辅助内容和装饰，不得优先压缩主内容。
- Auxiliary Degradation：对真实图片、应用场景标签、证明图、设备示意带、装饰背景等辅助内容定义标准 / 紧凑 / 极简三档。空间紧张时优先从标准降为紧凑或极简，主内容仍需保持可读和舒展。
- Anti-Flattening Rule：当主重点是 `reading-priority` 或 `path-priority` 时，不要为了突出重点而把页面铺满为均分模块。应保留视觉锚点、阅读路径、留白和层次关系，让重点通过阅读顺序、文本完整度、连接关系和材质层级突出。
- 模块优先级：必须保留、可缩小、可合并、可删除。
- 文本承载策略：说明本页是保留完整正文、压缩为模块，还是核心正文 + 模块混合；若用户要求保留定义、背景、结论等原文，应在此写明，不得过度摘要为卖点卡片。
- 必保小标题：列出本页必须出现的一级小标题，例如产品定义、应用场景、核心功能；这些标题应作为信息结构要求处理，不得仅因为锁定文本里没有出现就省略。
- 正文字号与排版策略：正文承载页的正文使用中等字号、稳定行距和正面二维排版，不使用展示型大字、窄体字、横向压缩字或透视面板文字；关键术语可局部高亮，但普通说明文字应保持正文层级。
- 内容完整性检查：列出原大纲中的一级信息组及其去向，例如定义、背景、应用场景、核心功能、建议重点等；可压缩或合并，但不得无声遗漏。
- 信息组权重检查：列出每个一级信息组的 `primary / secondary / supporting / light` 角色，以及对应处理方式。`primary` 组必须拥有最高阅读优先级或用户指定的重点表达方式；`supporting` 组可以是中等视觉锚点或证据带，但不得反客为主；`light` 组可图标化或标签化。
- 信息结构检查：检查 `required_section_titles` 是否全部有可见去向；若页面类型为阅读优先或正文承载，默认保留这些小标题。
- 文本保真预算：A 级必保原文、B 级可压缩摘要、C 级只做视觉表达；说明每个模块最多保留几行文字。对正文承载页，定义主段落可作为 A 级或高优先级 B 级，但仍需通过视觉分区、重点术语、产品图、架构层或侧栏摘要保持信息和视觉并重。
- 文字形态风险：如果需要在图片内生成较多中文正文，说明如何降低字形风险：扩大版心、减少每行字符密度、使用短句分段、避免透视文字、禁止横向压缩/竖向拉伸/笔画粘连。
- 布局、对齐参照与安全边距：
- 对齐失败预案：如果生成结果中上方模块、侧边模块、设备示意带或下方主模块没有共享明确边界，视为高影响版式失败；先重写蓝图为统一父框和固定列网格，再重生成，不要把它当作可接受的“视觉均衡”。
- 拥挤失败预案：如果标题安全和对齐通过，但主内容区显得过矮、行距过紧、模块压缩、文字拥挤或辅助内容抢占主内容空间，仍视为高影响信息设计失败；先降低辅助内容档位、减少装饰、重分配空间，再重生成。
- 平铺失败预案：如果生成结果只是把主重点做成满屏均分卡片、缺少视觉锚点/路径/场景关系，或比参考方向明显更平铺直叙，视为高影响信息设计失败。先把 `primary_emphasis_method` 改写为阅读/路径/视觉锚点表达，明确构图关系，再重生成。

## 审阅清单

- 风格和视觉模式是否合适。
- 标题、真实图片和锁定文本是否正确。
- 信息层级、布局和安全边距是否合理。
- 主内容是否足够舒展，核心矩阵/功能区/对比表/流程区是否没有被标题安全区或辅助内容挤压。
- 辅助内容是否已按空间需要降级，是否仍然抢占主内容空间。
- 页面类型和文本承载策略是否符合预期，尤其是否同意完整正文与模块化概览之间的取舍。
- 原大纲一级信息组是否都有明确去向，没有被无声遗漏。
- 正文是否为正文层级字号，且中文文字没有明显横向压缩、竖向拉伸、窄体化、透视变形或笔画粘连。
- 标题区与主体蓝图是否足以支持首轮生成，不依赖事后整体下移。
- 是否同意先生成样张。
