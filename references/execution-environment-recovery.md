# Unified single-page execution and recovery

For an exact board URL and request ID, use `scripts/page-task.mjs` from this skill directory for all execution commands. It routes screenshot and Markdown tasks automatically through the existing execution implementation. Follow `references/single-page-execution.md` for design, official image generation, QA and finalization, replacing its `page-execution.mjs` commands with `page-task.mjs`. Read the input package's `requiredReads`. Screenshot tasks also follow `references/screenshot-extraction.md`, including `record --extracted-source`.

Run `node scripts/page-task.mjs prepare --url <board-url> --request-id <exact-id>`. It verifies the assigned page, reads source/assets, checks saved execution identity and the preparation directories, then writes or resumes the actual immutable execution record. It returns `manifest` and `workerId`. Keep that worker ID for this chat and pass `--worker-id <workerId>` with every subsequent command and repeated prepare. An existing owner blocks a second chat. After confirming the original worker has stopped, another chat can use `prepare --confirm-stopped` with the same request ID to take over. Do not infer that a quiet heartbeat means the original worker stopped.

`inspect --url ... --request-id ...` performs read-only environment checks and reports `manifestExists` separately from its expected path. It does not establish project write capability. Preparation checks only guide/prompt directories and the actual execution-record write. `check --manifest ... --worker-id ... --include-prompt` verifies the output directories before returning the exact prompt and input images for the official tool. Check that `image_gen.imagegen` is available in the executing chat before start. The script cannot verify the chat's tool inventory or guarantee tool acceptance of an image input.

Permission errors return the original code, failing stage and `guidance`, and report the blocker to the assigned board when reachable. If the current session allows permission requests, request the access needed for that same already-authorized project operation and retry that exact command with the same worker ID. If policy explicitly denies approval, report that refusal and continue in a local project chat with the required access. Do not repeatedly request a forbidden approval or switch tools to circumvent a denied permission. A tool authorization prompt and filesystem write access are separate capabilities.

Failures leave request status and existing outputs intact. If image generation succeeded, preserve the official output and resume saving, QA or candidate registration with the same manifest. If screenshot backfill failed after candidate registration, retry complete with that candidate and extraction. Failed diagnostics do not create a replacement request. Report failures to contact the board separately from the original execution error. Existing legacy execution records remain usable through this entry without changing their frozen input fingerprint.
