# Sequential Page Board

Use only when the user wants to choose any page, generate one image, review it in the board, and then continue. Create a separate full copy of the existing V4.1 decision board with `node scripts/create-sequential-review-board.mjs <project-path>`, then start it with `node scripts/sequential-board-control.mjs start <project-path>`. The original `decision_board/` files and standard batch workflow remain intact. The new board is `decision_board_sequential/` and retains the original global settings, page choices, real-image uploads, source editor, save action, and generated-image browser. Its editable decision-version Markdown is copied into the new board so editing there does not alter the original board's source. Do not regenerate or overwrite an existing sequential board; it contains decisions and image acceptance records.

The added panel appears below each page's existing image browser. The user may choose any page. Clicking its generation button confirms the current page choices into the new board's `style_decision.json` and writes one request in `decision_board_sequential/page-flow-requests/<request-id>.json`. The board does not call `image_gen.imagegen`. It displays “等待 Codex 处理” until Codex posts a start receipt. At most one request may be queued, running, or awaiting confirmation across the project. The first accepted page is a formal page and counts toward completion.

Codex reads `GET /api/page-flow/requests/next` or the request file, verifies the source and decision hashes, then sends `POST /api/page-flow/run/start` with `{ "requestId": "..." }`. Build or refresh this page's guide and prompt when needed. Generate one body image with the official conversational image tool, run focused QA, finalize the title according to the confirmed mode, and save unique version names such as `body_image/slide_05_v003.png` and `final_image/slide_05_v003.png`. Preserve older files. Send `POST /api/page-flow/run/complete` with `{ "requestId": "...", "body": "body_image/slide_05_v003.png", "final": "final_image/slide_05_v003.png", "qa": "...", "guideHash": "...", "promptHash": "..." }`. On failure, send `POST /api/page-flow/run/fail` with the request ID and a short error. These run endpoints are local only and accept Codex's local request without a browser Origin header. Do not claim generation started until the start receipt succeeds.

The user adopts, rejects, or requests a redo in the new panel. Adoption records the exact final image file and source and decision hashes, then selects the next unfinished page while still allowing free navigation. A source or decision change marks an adopted page for review but preserves its old image and record. Existing images of unknown lineage remain visible in the original browser as historical versions and are not automatically adopted.

After all intended pages have adopted versions, check page completeness, source and decision validity, title safety, visual consistency, and final image dimensions. Reopen only pages with an actual issue. The standard `final_image/slide_XX.png` delivery aliases may be produced from accepted version files during final delivery, preserving prior files before any replacement.
